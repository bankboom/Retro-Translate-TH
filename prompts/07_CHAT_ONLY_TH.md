# คำสั่งแปลเกมผ่านแชต — ใช้กับ Codex หลังติดตั้งครั้งเดียว

## คำสั่ง 1: เกมใหม่
"ใช้คู่มือ V3.2 แปลเกมนี้เป็นภาษาไทย: <พาธไฟล์ ROM> เน้นเนื้อหาถูกต้อง ฟอนต์ไทยสวย และประหยัดโทเคน"
- เลือกไฟล์ที่ผู้ใช้แนบ/ระบุจริง ไม่เดาชื่อไฟล์หรือหา ROM ทั่วทั้งเครื่อง
- สร้างโครงการอัตโนมัติ (ไม่ให้ผู้ใช้สร้างโฟลเดอร์)
- ตรวจ G0 ก่อนและนำเสนอ micro-patch 1–5 รายการเมื่อเทคนิคพร้อม

## คำสั่ง 2: เกมเดิม
"ใช้คู่มือ V3.2 ทำเกม <ชื่อเกม> ต่อจากจุดล่าสุด"
- ให้ Codex ใช้ `chat_project.py find --game "<ชื่อเกม>"` เปิด project_profile.json เดิม ไม่สร้างใหม่ถ้า identity เดียวกัน
- อ่าน docs/NEXT_TASK.md + gates/status + diff เฉพาะช่วงล่าสุด
- อย่ากลับไปแปลรายการที่อนุมัติแล้ว

## คำสั่ง 3: ฟอนต์ไทย
"ใช้คู่มือ V3.2 ตรวจฟอนต์ไทยของ <ชื่อเกม> จากภาพ/คลิปนี้"
- ตรวจภาพฉากเดียวกัน ฟอนต์ขนาดเดียวกัน
- ตรวจ อำ น้ำ สำ ต้ ตุ เก่ง ปัญหา ภาษา และเคสซ้อนสระ/วรรณยุกต์
- รายงานเฉพาะ glyphs/offsets ที่เปลี่ยน; ยังไม่เห็นในอีมูเลเตอร์ให้คง G3 PENDING

## คำสั่ง 4: QA ก่อนเผยแพร่
"ใช้คู่มือ V3.2 ตรวจแพตช์ล่าสุดของ <ชื่อเกม> ตาม G0–G5"
- ตรวจฐาน clean ROM, CRC/hash, translated vs injected vs visual-confirmed
- ห้ามรายงาน '100%' ถ้าหลักฐานไม่ครบ

## เมื่อขาดข้อมูล
ถามผู้ใช้เพียง 1 รายการที่จำเป็น เช่น ROM ที่ Codex เปิดอ่านได้, revision ที่ตรงแพตช์ หรือภาพหน้าจอ Emulator; อย่าขอข้อมูลซ้ำถ้ามีอยู่แล้ว.

## ประหยัดโทเคนโดยไม่ลดคุณภาพ
- ประมวล binary, diff, CSV, mapping ด้วย Python/CLI ก่อนส่ง AI
- ใช้ bounded packet เฉพาะ context + IDs ที่ต้องแปล; บันทึก batch checkpoint
- ทำ approved glossary/TM ตาม context, ไม่คัดลอกแปลอัตโนมัติแบบไร้บริบท
- เก็บ cache จากงานเดิม ไม่อ่านเอกสารทั้งหมดทุกเทิร์น
- ตรวจ QA เฉพาะส่วนที่เปลี่ยน และทดสอบ regression เฉพาะส่วนสำคัญ

## คำสั่งเสริม: ใช้คำแปลร่วมจากเกมภาคก่อน
"ใช้คู่มือ V3.2 และระบบ Cross-Project Translation Memory ตรวจคำแปลที่อนุมัติแล้วจากเกมภาคก่อน ๆ ใน workspace เพื่อเสนอใช้ซ้ำกับเกมปัจจุบัน ตรวจบริบทก่อนรับคำแปลทุกครั้ง และรายงานผลโดยประหยัดโทเคน"
- อ่าน `prompts/08_CROSS_PROJECT_MEMORY_TH.md` เฉพาะเมื่อต้องการ reuse.
