# Six-Phase Emulator-First + Context QA (คู่มือกลางสำหรับทุกเกม)

**เป้าหมาย:** แพตช์ทดลองเข้าสู่ Emulator ให้เร็วที่สุด **อย่างปลอดภัย** พร้อมตรวจความหมายภาษาไทยตามบริบท **ในทุกเฟส** ไม่ใช่รอ Phase 5 หรือ Final QA. เอกสารนี้ใช้ได้ข้ามเกม/ค่าย/เครื่อง และไม่สมมติว่าเกมทุกเกมมี codec/renderer เหมือนกัน

## 6 เฟสของโครงการ (ไม่นับ G0–G5 เป็นเฟสเพิ่ม)

| เฟส | ผลลัพธ์ที่ต้องพยายามส่งมอบ | Context/Translation QA ที่ทำในเฟส | Emulator / เงื่อนไข |
| --- | --- | --- | --- |
| **Phase 1 — Safe micro-patch** | ตรวจ ROM (G0), ค้นข้อความที่แสดงจริง 1–5 รายการ, สร้างแพตช์ทดลองที่ย้อนกลับได้ | เทียบ source/คำสั่ง/บริบทของ *เฉพาะข้อความทดลอง*; ถ้าใช้ ASCII smoke เพื่อพิสูจน์การใส่ข้อความ ให้ระบุว่าไม่ใช่แพตช์แปลไทย | สร้าง candidate ได้จริงจึงส่งให้ Emulator; ไม่ต้องรู้ทุก event/ARM |
| **Phase 2 — Emulator + Thai font** | ทดสอบบูต/เมนู, ทดลองอักษรไทย, สระและวรรณยุกต์ | ดู source เทียบข้อความที่ปรากฏในฉากจริง ตรวจน้ำเสียง พื้นที่ข้อความ และผู้พูด; พบผิดให้กลับไปแก้เฉพาะ ID | บันทึก build, emulator/version, scene, screenshot/log; ไม่มีหลักฐานคง PENDING |
| **Phase 3 — 50%** | ขยายคำแปลและแพตช์ตาม **ขอบเขตข้อความที่ตรวจพบและยืนยันแล้ว** | ตรวจทุกแถวที่นับว่า REVIEWED ตามรายการตรวจ 6 ข้อ และทดสอบเฉพาะ bank/scene ที่แก้ | ทำแพตช์ 50% และทดสอบเฉพาะเมื่อ builder ปลอดภัย; Draft 50% ไม่ใช่ Reviewed 50% |
| **Phase 4 — 70%** | เพิ่มเนื้อเรื่อง บทสนทนา ระบบเกม | ตรวจความต่อเนื่องข้ามฉาก ผู้พูด/บุคลิก และศัพท์/กฎเกม; เทียบรายการที่เปลี่ยนกับ glossary/TM | ทดสอบฉากใหม่และ regression ฉากเดิม |
| **Phase 5 — 100% ตาม scope** | แปลครบรายการในขอบเขตที่ยืนยันว่าค้นพบแล้ว | ตรวจข้อผิดพลาดข้ามเรื่อง ชื่อ ตัวแปร ข้อความยาว และรายการ NEEDS_CONTEXT ที่ยังเปิดอยู่ | ทดสอบแพตช์ 100% **ตาม scope**; ห้ามเรียกทั้งเกม 100% เมื่อยังมี archive/ข้อความที่ไม่แมป |
| **Phase 6 — Final QA & release** | สรุป G0–G5, แพตช์ BPS/อื่น ๆ, manifest และ rollback | ตรวจทวนข้อความจากการเล่นจริง สุ่มตรวจซ้ำการสะกด บริบท และ glossary; แก้ regression ทุกประเด็นที่มีนัยสำคัญ | G3/G4 จาก Emulator จริง, G5 ต้องมีหลักฐานและการอนุมัติ; ไม่ผ่านห้ามประกาศ Release |

**ลำดับสั้น:** ดึงข้อความ → แปลทีละชุด → ตรวจบริบทที่ทราบ → สร้าง candidate ปลอดภัย → Emulator → ปรับคำแปล/ฟอนต์ → เพิ่มข้อความตามเป้าหมาย 50/70/100 → Final QA.

## Checklist ตรวจคำแปล 6 เรื่อง (ใช้ตั้งแต่ข้อความแรก ทุกชุด ไม่เพิ่มเอกสารซ้ำ)

1. **Meaning:** ความหมายและค่ากติกา/เงื่อนไข/จำนวนไม่เปลี่ยน
2. **Context:** ฉาก ผู้พูด ผู้รับสาร เหตุการณ์ และเจตนาตรงกัน; ถ้าไม่รู้จริงต้องระบุไม่ยืนยัน
3. **Thai:** สะกด ไวยากรณ์ น้ำเสียง สำนวนเป็นธรรมชาติ
4. **Terminology:** ชื่อตัวละคร ทักษะ ไอเทม สถานที่สอดคล้องกับ glossary ที่ผ่านตรวจ
5. **Continuity:** บทสนทนาก่อน/หลัง และเกมภาคอื่นที่ได้รับการยืนยัน ไม่ขัดกัน; **ไม่คัดลอกคำแปลเพียงเพราะค่ายหรือซีรีส์ตรง**
6. **Technical:** control codes, placeholders, ตัวเลข, IDs, newline, encoding, ความกว้าง/พื้นที่ UI ไม่เสีย; ตรวจภาพจริงเมื่อเข้าถึง

ถ้าไม่มีหลักฐานเรื่องบริบท **ห้าม** เปลี่ยนเป็น REVIEWED จากการเดา เช่น ชื่อไฟล์ `story` ไม่พิสูจน์ผู้พูดในเกมจริง ใช้ภาพหน้าจอ วิดีโอ ตัวเกม บริบทรอบ ID และหลักฐานต้นฉบับเท่าที่เข้าถึงได้

## สถานะที่ไม่ควรปะปนกัน

- **TranslationStatus**: `DRAFT` = มีคำแปลเบื้องต้น, `NEEDS_CONTEXT` = ความหมายหรือฉากยังไม่ชัด, `REVIEWED` = ผ่าน 6 ข้อตามหลักฐานที่หาได้และ reviewer ระบุเหตุผล
- **InjectionStatus**: `NOT_INJECTED` / `INJECTED` = ตำแหน่งข้อความยังไม่ถูก/ถูกใส่ใน candidate; ไม่พิสูจน์การแสดงผลหรือ QA ภาษา
- **IN_GAME_VERIFIED**: หลักฐานว่าข้อความ ID นั้นถูกพบและตรวจใน Emulator จาก build/version/scene ที่ระบุ; บันทึกไว้ใน QA report หรือ field ที่ schema รองรับ ไม่บังคับเปลี่ยน `TranslationStatus`/แก้ schema เดิม
- **SMOKE_READY / EMULATOR_NOT_RUN / SMOKE_PASS / SMOKE_FAIL**: สถานะแพตช์ทดลองแยกจาก G0–G5; ไม่ยืนยันว่าแปลทั้งเกมครบ

**ข้อยกเว้นสำคัญสำหรับ Phase 1:** technical smoke แบบ ASCII ที่ยังไม่ใช่คำแปลภาษาไทยให้ทำก่อน contextual QA ของทั้ง bank ได้ เพื่อทดสอบ injector; ห้ามรายงานว่าเป็นคำแปล REVIEWED หรือ Thai font PASS. หากเป็น Thai micro-patch ให้ตรวจบริบทของ 1–5 แถวก่อนเมื่อมีหลักฐาน; ถ้ายังมีข้อมูลไม่พอสามารถทดสอบแบบชั่วคราวโดยระบุ `DRAFT/NEEDS_CONTEXT` ชัด ๆ แต่ห้ามนำไปนับเป็นแถวอนุมัติหรือแพตช์เผยแพร่

## หลักฐานขั้นต่ำต่อรายการ REVIEWED

ระบุ `Bank + ID`, ต้นฉบับ, คำแปล, `Context_Key`/`Scene`/`Speaker` เท่าที่ทราบ, เหตุผล QA หรือรายการตรวจใน `QA_Note`, ผู้ตรวจ/แหล่งอ้างอิง (เมื่อมี), control tokens ที่รักษาไว้. ห้ามสร้างฉาก/ผู้พูดหรือการตรวจที่ไม่ได้ทำ. ใช้ CSV schema เดิมได้ ไม่จำเป็นต้องเพิ่มคอลัมน์ทั้งหมดให้ทุกโปรเจกต์

## การวัดผลจริง (ประหยัดโทเคน ไม่รายงานเปอร์เซ็นต์หลอก)

- แสดง `Discovered / Draft / Needs context / Reviewed / Injected / In-game verified` แยกกัน พร้อมตัวหารที่ยืนยันได้
- 50% / 70% / 100% ในชื่อแพตช์ต้องระบุว่าเป็น **draft coverage** หรือ **reviewed coverage** และครอบคลุม banks ใด; อย่าอ้างความสำเร็จทั้งเกมถ้ามี text archive ที่ยังไม่วิเคราะห์
- ให้ AI ตรวจเฉพาะ `DRAFT/NEEDS_CONTEXT` ที่เปลี่ยนหรือมีบริบทเพิ่ม ใช้คำแปลข้ามเกมที่ `REVIEWED` และบริบทตรงเป็น candidate เท่านั้น
- เมื่อมีภาพ Emulator พบปัญหา ให้ downgrade เฉพาะรายการที่กระทบเป็น `NEEDS_CONTEXT` หรือ `DRAFT` แล้วตรวจใหม่ ไม่ย้อนไปแปลทั้งไฟล์
